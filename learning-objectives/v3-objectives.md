# Python for Cloud & AI Learning Objectives

*Last updated fall 2026*

| Week | Title | Learning outcomes |
|---|---|---|
| **1** | Production Python | • Define classes with attributes and methods, and use objects to bundle data with the behavior that belongs to it.<br>• Use `dataclasses`, type hints, and docstrings to write code that documents itself.<br>• Define and validate data schemas at my program's boundaries with Pydantic.<br>• Write `pytest` tests that check both the success path and the failure path.<br>• Split a script into importable modules and a package with its own test suite. |
| **2** | Supervised Machine Learning: Regression | • Explain what machine learning is, and where supervised learning and regression fit in the landscape.<br>• Use scikit-learn's `create → fit → predict` API to train a model.<br>• Train and evaluate a linear regression model on daily weather data using RMSE and R².<br>• Reason about how adding features changes a model's predictions and its error. |
| **3** | Classification and Model Deployment | • Prepare data for a classifier by scaling numeric features and one-hot encoding categorical ones, all inside a scikit-learn `Pipeline`.<br>• Build k-Nearest Neighbors and Logistic Regression classifiers on the weather data.<br>• Evaluate a classifier with accuracy, precision, recall, F1, and the confusion matrix.<br>• Choose which model to deploy based on how it will be used, not accuracy alone.<br>• Save a trained model to disk with `joblib`, then load it in a separate script and predict. |
| **4** | From Model to Reusable Component | • Refactor a training-and-prediction script into a class with a clean `predict()` method.<br>• Load a saved model once in `__init__` and reuse it for many predictions.<br>• Add type hints, docstrings, and input validation so the component is safe and self-documenting.<br>• Write `pytest` tests that cover both correct predictions and error handling.<br>• Package the `WeatherClassifier` as a `weather_model` component that any script can import. |
| **5** | Introduction to AI: LLMs and Prompt Engineering | • Explain how large language models work at a high level, from tokenization to embeddings.<br>• Call the OpenAI Chat Completions API and control outputs with parameters like temperature and `max_tokens`.<br>• Build a chatbot that holds a coherent conversation by managing message history.<br>• Apply prompt-engineering techniques: zero-shot, one-shot, few-shot, and chain-of-thought.<br>• Weigh the ethical questions that come with deploying AI systems, including bias and responsible use. |
| **6** | Augmenting AI: RAG | • Compare the main strategies for augmenting an LLM's knowledge: context injection, fine-tuning, and retrieval-augmented generation (RAG).<br>• Build a keyword-based RAG pipeline from scratch to make the retrieve, inject, and generate loop concrete.<br>• Use LlamaIndex to build a semantic RAG pipeline with chunking, embeddings, and cosine similarity.<br>• Evaluate a RAG system's answers for faithfulness and relevancy. |
| **7** | AI Agents | • Explain what an AI agent is, and how the ReAct (reason and act) loop differs from a single LLM call.<br>• Define tools with clear schemas and wire them into an agent's dispatch logic.<br>• Build agents both from scratch and with the smolagents framework.<br>• Distinguish tool-based from code-based agents, and judge where agents are genuinely useful. |
| **8** | Introduction to Cloud Computing | • Explain the core cloud concepts: IaaS, PaaS, SaaS, managed services, and scaling models.<br>• Orient myself in the cloud-provider landscape, from the hyperscalers to developer-tier and backend-as-a-service platforms.<br>• Map data-engineering needs — compute, storage, databases, and LLM and ML services — across providers.<br>• Estimate the cost of a cloud workload, and explain why this course uses Supabase. |
| **9** | Data in the Cloud | • Connect a Python script to a Supabase database, keeping credentials in environment variables rather than source code.<br>• Design the two-table schema, `weather_raw` and `weather_enriched`, that the rest of the course builds on.<br>• Read and write rows with the supabase-py SDK, using `upsert` with `on_conflict="date"` so every run is idempotent.<br>• Build an Extract and Load pipeline that pulls a year of daily weather from a public API into `weather_raw`. |
| **10** | LLMs in Pipelines | • Explain where a machine learning model and an LLM each belong in an ETL pipeline.<br>• Run the `WeatherClassifier` component over database records to label each day, processing only new dates.<br>• Design a constrained prompt so an LLM writes a one-sentence recommendation, and write the results to `weather_enriched`.<br>• Wrap the double-transform into a Prefect flow of `@task`s combined in a `@flow`. |
| **11** | Cloud ETL Capstone | • Assemble a four-task Prefect flow — extract, load raw, transform, and load enriched — from scratch.<br>• Apply production patterns: retries, `raise_for_status()`, structured logging, and idempotent writes.<br>• Run and observe the pipeline in the Prefect UI, reading both a successful run and a failed one.<br>• Reflect on what it would take to run the pipeline on a daily schedule in the cloud. |
